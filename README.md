# Workout Manager

> 매일의 기록을 모아 내 몸의 변화를 이해하고, 다이어트를 꾸준히 이어가기 위한 개인용 운동 보조 앱 프로젝트입니다.

## 이 프로젝트를 시작한 이유

누나의 결혼식을 준비하던 때였습니다. 가족에게는 설레는 행사를 기다리는 시간이었고, 저에게는 미뤄 두었던 다이어트를 시작할 분명한 이유가 생긴 시간이었습니다. 막연히 “살을 빼야지”라고 생각하는 데서 그치지 않고, 실제로 내 몸이 어떻게 변하고 있는지 알고 싶었습니다.

처음에는 체중만 재면 충분할 것 같았습니다. 하지만 체중 하나만으로는 오늘 먹은 음식과 운동이 어떤 영향을 주었는지, 근육은 유지되고 있는지, 지금의 방향이 맞는지 알기 어려웠습니다. 인바디 결과는 따로 있고, 식단과 운동 기록은 흩어져 있었으며, 숫자는 많아도 그 숫자를 하나의 흐름으로 읽기는 쉽지 않았습니다.

그때 가장 자연스러운 답은 늘 곁에 있는 핸드폰이었습니다. 특별한 장비나 계속 켜 두어야 하는 컴퓨터 없이, 아이폰으로 먹은 단백질과 칼로리를 기록하고 운동을 남기며 인바디 변화를 확인할 수 있다면 몸의 상태를 훨씬 꾸준히 살펴볼 수 있다고 생각했습니다.

그렇게 Workout Manager를 구상하게 되었습니다. 이 프로젝트는 단순히 체중을 줄이라는 앱이 아니라, 흩어진 기록을 연결해 내 몸의 변화를 이해하도록 돕는 도구를 만드는 시도입니다. 한 번의 좋은 숫자보다 긴 흐름을 보고, 확실한 사실과 아직 모르는 부분을 구분하며, 다음 행동을 결정할 수 있는 앱을 목표로 합니다.

## 현재 상태

이 저장소는 **실행 가능한 앱 코드 저장소가 아니라, Workout Manager MVP의 확정 명세와 개발 원칙을 공개하는 문서 저장소**입니다.

- MVP 범위는 현재 잠겨 있습니다.
- 구현 중 임의로 기능을 추가하거나 확정 기능을 제거하지 않습니다.
- 이 저장소에는 실제 건강 데이터, 비밀번호, API 키 또는 서버 비밀값이 없습니다.
- 실제 구현은 이 명세를 기준으로 별도 작업합니다.

전체 범위는 [`docs/MVP_SPEC.md`](docs/MVP_SPEC.md)에서 확인할 수 있습니다.

## 만들고자 하는 것

Workout Manager의 첫 버전은 아이폰 홈 화면에 설치할 수 있는 PWA로 시작합니다.

- 오늘 먹은 단백질과 칼로리를 여러 번 빠르게 기록
- 단백질 최소선·권장 범위와 남은 칼로리 범위 표시
- InBody 엑셀 또는 CSV 업로드와 중복 측정 방지
- 체중·골격근량·체지방률 등 주요 지표의 장기 변화 확인
- 실제 운동 수행 여부와 시간 기록
- 식단·운동·인바디 데이터를 함께 보는 요청형 AI 코칭
- 불확실한 외식 기록을 단일 숫자가 아닌 최소~최대 범위로 관리
- 2~3주 이상의 충분한 기록을 바탕으로 TDEE를 점진적으로 보정

AI 답변은 `확인된 사실 / 가능한 원인 / 데이터 부족 / 다음 행동`으로 나눕니다. 수치 계산은 코드가 담당하고, AI는 해석과 설명을 담당합니다.

## 화면 구성

1. **홈**: 오늘의 단백질·칼로리 상태와 인바디 핵심 요약
2. **기록**: 식단 및 운동 빠른 입력과 당일 기록
3. **신체변화**: 인바디 측정 요약, 상세 분석 및 변화 그래프
4. **AI 코치**: 변화 리포트와 사용자가 요청한 상담

## 기술 방향

```text
아이폰 PWA / 브라우저
        ├─ 일반 CRUD ─────────────→ Supabase Auth + PostgreSQL + RLS
        └─ AI·비밀 작업 ─────────→ Cloudflare Worker ─→ OpenAI 또는 관리자 작업
```

- 프론트엔드와 정적 배포는 Cloudflare를 사용합니다.
- 일반 데이터 작업은 Supabase Auth와 RLS를 사용합니다.
- Cloudflare Worker는 서버 비밀키, AI 호출, 관리자 작업과 사용량 제한에만 사용합니다.
- 모든 사용자 소유 데이터는 `user_id`로 인증 사용자와 연결합니다.
- 데이터베이스 변경은 SQL migration으로 추적합니다.
- 무료 플랜을 우선하되 보안과 데이터 무결성을 희생하지 않습니다.

## 보안과 개인정보 원칙

건강 데이터는 개인에게 민감한 정보이므로 처음부터 다음 원칙을 지킵니다.

- 사용자별 데이터에 RLS를 적용해 자신의 행에만 접근
- 건강 데이터 접근 시 TOTP 기반 다중 인증과 `aal2` 세션 요구
- `service_role`, OpenAI API 키, DB 비밀번호를 브라우저나 Git에 포함하지 않음
- 서버 비밀값은 Cloudflare Secrets 등 서버 전용 저장소에서만 관리
- InBody 원본 파일은 브라우저에서 파싱하고 기본적으로 서버에 보관하지 않음
- AI에는 해석에 필요한 최소 데이터만 전달하고 불필요한 식별정보는 제외
- AI 출력은 실행 가능한 코드나 신뢰된 HTML로 취급하지 않음
- 건강 수치와 비밀값을 애플리케이션 로그에 기록하지 않음

## 아쉬웠던 점과 현재의 한계

### 원하는 만큼 자동화할 수 없었습니다

가장 편한 방식은 InBody 앱의 결과가 자동으로 들어오는 것이지만, 공식 연동은 계약과 비용이 필요할 수 있고 비공식 API는 안정성과 계정 보안을 보장하기 어렵습니다. 그래서 MVP에서는 자동 동기화를 포기하고 아이폰에서 엑셀 또는 CSV를 직접 올리는 방식을 선택했습니다. 한 단계 더 손이 가지만 핵심 기능이 외부 서비스의 변화에 흔들리지 않는 쪽을 택했습니다.

### 숫자가 많다고 언제나 더 정확한 것은 아닙니다

체중과 체성분은 수분 상태, 식사, 운동, 측정 시간에 따라 달라질 수 있습니다. 앱은 한 번의 측정값을 정답처럼 판단하기보다 장기 추세를 보여 주도록 설계했지만, 기록이 적거나 측정 조건이 크게 다르면 해석에도 한계가 있습니다.

### 맞춤형 칼로리 판단에는 시간이 필요합니다

초기 TDEE는 BMR과 활동량을 바탕으로 계산할 수 있지만, 개인에게 맞게 보정하려면 2~3주 이상의 비교적 완전한 식단과 체중 기록이 필요합니다. 기록이 불완전한 날이 많다면 앱도 성급한 결론을 내려서는 안 됩니다.

### 기존 AI 상담을 자동으로 이어받을 수 없습니다

개인 ChatGPT 프로젝트의 과거 대화를 앱이 자동으로 읽는 기능은 MVP에 포함하지 않았습니다. 기존 운동 계획은 사용자가 정리한 요약을 가져오는 방식으로 시작합니다. 불편함은 있지만 서비스 간 권한과 개인정보 경계를 억지로 넘지 않기 위한 선택입니다.

### 첫 버전은 한 사람을 위한 제품입니다

데이터 구조와 인증은 여러 사용자로 확장할 수 있게 설계하지만, 첫 버전에서는 본인 계정만 허용합니다. 공개 회원가입, 관리자 대시보드, 결제 기능은 아직 다루지 않습니다. 처음부터 모든 서비스를 만들기보다 실제로 매일 사용할 수 있는 개인용 도구를 먼저 완성하려 합니다.

### 이 저장소만으로 앱을 실행할 수 없습니다

현재 공개 저장소에는 구현 코드와 배포 설정이 없고 확정 명세만 있습니다. 따라서 설치, 실행, 테스트 방법도 아직 제공하지 않습니다. 구현 코드가 공개되는 시점에는 별도의 실행 방법과 보안 검증 결과가 필요합니다.

## 만들면서 느낀 점

다이어트 기록에서 중요한 것은 모든 숫자를 정확하게 채우는 일이 아니라, 무엇을 알고 무엇을 모르는지를 솔직하게 남기는 일이라고 생각하게 되었습니다. 그래서 `-`는 `0`이 아니며, 외식 칼로리는 거짓으로 정밀한 한 숫자보다 범위가 낫고, 데이터가 없는 부위 분석은 만들어 내지 않는다는 원칙을 세웠습니다.

AI도 같은 기준을 따라야 합니다. 그럴듯한 답을 빠르게 만드는 것보다 확인된 사실과 추정, 데이터 부족을 구분하는 편이 실제 행동을 정하는 데 더 도움이 됩니다. Workout Manager는 사용자를 대신해 결정을 내리는 앱보다, 사용자가 자기 몸을 더 잘 이해하도록 돕는 앱에 가깝습니다.

## 안내

- 이 프로젝트는 의료기기나 의료 진단 서비스가 아닙니다. 건강상 우려가 있다면 의료 전문가와 상담해야 합니다.
- InBody는 데이터 출처를 설명하기 위해 언급되며, 이 프로젝트는 InBody 및 언급된 외부 서비스와 제휴하거나 공식 인증을 받은 프로젝트가 아닙니다.
- 공개 저장소에는 개인 건강 데이터와 서비스 비밀값을 커밋하지 않습니다.
