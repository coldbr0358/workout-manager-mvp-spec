# Workout Manager MVP 확정 명세

- 상태: **LOCKED**
- 확정일: 2026-08-27
- 변경 조건: 사용자의 명시적인 승인

## 1. 제품 목표

다이어트 중인 사용자가 식단, 운동 및 인바디 변화를 한곳에서 기록하고, 근거 수준이 구분된 AI 코칭을 받을 수 있는 개인용 운동 보조 앱을 만든다.

현재는 한 명이 편하게 사용하는 것을 최우선으로 하되, 데이터와 인증 구조는 나중에 여러 사용자에게 공개해도 처음부터 다시 만들 필요가 없도록 설계한다.

## 2. 확정된 사용자 경험

### 앱 제공 방식

- 아이폰 홈 화면에 설치할 수 있는 PWA로 시작한다.
- 필요해지면 동일한 API와 데이터 구조를 사용하는 네이티브 앱으로 확장한다.
- 앱 사용을 위해 계속 켜진 노트북이나 라즈베리 파이를 요구하지 않는다.

### 통합 홈

- 상단에 오늘의 단백질 최소선과 권장 범위, 섭취 칼로리, 적응형 칼로리 목표 및 남은 범위를 표시한다.
- 하단에 인바디 핵심 지표인 체중, 골격근량, 체지방률과 사용자가 선택한 지표의 추세 그래프를 표시한다.

### 인바디 가져오기와 표시

- 아이폰에서 InBody 엑셀 또는 CSV 파일을 업로드한다.
- 전체 이력 파일을 반복해서 업로드해도 기존 측정은 중복 저장하지 않고 신규 측정만 추가한다.
- CSV의 모든 열을 보존한다.
- `-`, 빈 문자열 및 장비가 제공하지 않은 값은 `0`이 아니라 미측정 값으로 처리한다.
- 자주 쓰는 지표를 우선 표시하고 고급 지표는 값이 있을 때만 표시한다.
- 신체변화 화면에서 측정 요약, 지표별 상세 범위, 장기 변화 그래프 및 데이터가 존재하는 부위별 분석을 제공한다.
- 인바디 화면의 정보 구조는 참고하되 상표, 그래픽 및 화면을 그대로 복제하지 않는다.

### 식단 기록

- 하루 동안 단백질 g과 칼로리를 여러 번 빠르게 추가할 수 있다.
- 영양성분표 사진은 AI가 값을 추출하되 사용자가 확인한 뒤에만 저장한다.
- 외식처럼 정확한 값이 없는 기록은 최소~최대 추정 범위와 불완전 상태를 지원한다.
- 하루 합계와 칼로리 적자 계산에도 추정 범위를 유지한다.
- 단백질 목표는 단일 정답 대신 최소선과 권장 범위로 표시하며 사용자가 수정할 수 있다.

### 운동 기록과 코치

- 기존 ChatGPT 운동 프로젝트에서 정리한 루틴 요약을 앱에 가져와 기준 계획으로 저장한다.
- 앱에서 실제 운동 부위, 수행 여부 및 시간을 기록한다.
- 앱 내 AI 코치는 저장된 운동 계획, 실제 운동 기록, 식단 및 인바디 데이터를 함께 사용한다.
- 개인 ChatGPT 프로젝트의 기존 대화 내용을 앱이 자동으로 읽는 기능은 MVP 범위가 아니다.
- AI가 제안한 계획 변경은 사용자가 확인해야 저장된다.

### 칼로리와 TDEE

- 최신 BMR, 기본 활동량 및 운동 계획으로 초기 TDEE를 계산한다.
- 운동한 날의 추정 소비 칼로리를 당일 식사 예산에 전부 더하지 않는다.
- 충분히 완전한 식단 및 체중 데이터가 2~3주 이상 쌓이면 체중 추세로 TDEE를 점진적으로 보정한다.
- 기록이 불완전한 날은 적응 계산에서 제외한다.

### AI 분석

- 새 인바디 측정이 추가될 때 변화 리포트를 한 번 생성한다.
- 그 외에는 사용자가 분석 버튼이나 채팅으로 요청할 때만 AI를 호출한다.
- 동일한 입력 데이터의 분석 결과는 재사용한다.
- 응답은 `확인된 사실 / 가능한 원인 / 데이터 부족 / 다음 행동`으로 구분한다.
- 수치 계산은 결정론적 코드가 담당하고 AI는 해석과 설명을 담당한다.
- 의료 진단을 제공하지 않으며 필요한 경우 전문가 상담을 안내한다.

## 3. 화면 구조

하단 내비게이션은 다음 네 영역으로 구성한다.

1. **홈**: 오늘의 단백질·칼로리 상태와 인바디 핵심 요약
2. **기록**: 식단 및 운동 빠른 입력과 당일 기록
3. **신체변화**: 인바디 측정 요약, 상세 분석 및 변화 그래프
4. **AI 코치**: 변화 리포트와 요청형 상담

설정과 계정 보안은 별도 설정 화면에서 제공하며 제품의 주요 탭으로 만들지 않는다.

## 4. 확정 아키텍처

```text
아이폰 PWA / 브라우저
        ├─ 일반 CRUD ─────────────→ Supabase Auth + PostgreSQL + RLS
        └─ AI·비밀 작업 ─────────→ Cloudflare Worker ─→ OpenAI 또는 관리자 작업
```

- 프론트엔드와 정적 배포는 Cloudflare를 사용한다.
- 일반 사용자 CRUD는 Supabase 공개용 키와 RLS로 직접 수행한다.
- Worker는 일반 CRUD를 대신하지 않는다.
- Worker는 OpenAI 호출, 서버 비밀키가 필요한 외부 연동, 관리자 권한 작업 및 서버 측 사용량 제한에만 사용한다.
- 데이터베이스는 Supabase PostgreSQL, 인증은 Supabase Auth를 사용한다.
- 사용자 소유 데이터에는 `user_id`를 포함하고 Auth 사용자 ID와 연결한다.
- DB 변경은 SQL migration으로 추적한다.

## 5. 보안과 데이터 무결성

- 첫 버전은 본인 계정만 허용하고 공개 회원가입을 비활성화한다.
- 로그인은 이메일, 강한 비밀번호 및 Google Authenticator TOTP를 사용한다.
- 건강 데이터 접근 정책은 다중 인증이 완료된 `aal2` 세션을 요구한다.
- 사용자별 테이블은 RLS로 자신의 행만 읽고 쓸 수 있게 한다.
- Supabase `service_role`, OpenAI API 키 및 DB 비밀번호는 프론트엔드와 Git에 넣지 않는다.
- 서버 비밀값은 Cloudflare Secrets 또는 해당 서비스의 안전한 비밀 저장소에만 둔다.
- 인바디 원본 엑셀은 브라우저에서 파싱하고 기본적으로 서버나 Storage에 보관하지 않는다.
- AI에는 분석에 필요한 최소 기간과 지표만 보내며 이메일 등 불필요한 식별정보를 제외한다.
- AI 출력은 실행 가능한 코드나 신뢰된 HTML로 취급하지 않는다.
- 파일 형식, 크기, 열, 값 범위 및 중복을 검증한 뒤 저장한다.
- 민감한 건강 수치와 비밀값을 애플리케이션 로그에 기록하지 않는다.
- 본인 OpenAI API 키는 Worker에 저장하고 사용자별 호출량, 토큰 및 월 예산 한도를 적용한다.
- 데이터 내보내기와 계정 데이터 삭제가 가능하도록 구조를 설계한다.

## 6. MVP에서 제외하거나 연기한 기능

- 비공식 InBody API 자동 동기화
- 공식 InBody 유료 API 계약 및 OAuth 연동
- 네이티브 iOS 앱과 HealthKit 직접 연동
- 외부 사용자에게 공개된 회원가입
- 관리자 대시보드와 결제 시스템
- 매일 자동 생성되는 AI 리포트
- AI가 사용자 확인 없이 운동 계획이나 건강 데이터를 변경하는 기능
- 데이터가 없는 부위별 분석을 추정하거나 만들어 표시하는 기능

비공식 InBody API는 향후 읽기 전용 실험 기능으로만 검토하며, 실패해도 엑셀 가져오기와 핵심 앱 기능에 영향을 주지 않아야 한다.

## 7. MVP 범위 잠금 규칙

- 이 문서의 기능 목록이 MVP의 확정 범위다.
- 구현 과정에서 새로운 제품 기능을 임의로 추가하지 않는다.
- 새로운 아이디어는 백로그 후보로만 기록하고 사용자 승인 전에는 구현하지 않는다.
- 보안, 데이터 무결성, 접근성 또는 확정 기능의 정상 동작에 반드시 필요한 기술 작업은 범위 내에서 최소한으로 수행할 수 있다.
- 가장 단순한 구조를 우선하며 불필요한 서비스, Worker 호출, DB 요청, AI 호출 및 파일 저장을 만들지 않는다.
- 범위 변경은 이 문서의 상태와 변경 이력을 갱신할 수 있을 정도로 사용자가 명시적으로 승인한 경우에만 허용한다.
